JellyCAP

Generate reviewable collection metadata from the collection's own contents. TV context stays at show level; seasons and episodes are excluded.

Required for OpenAI-compatible providers. Requests originate from the Jellyfin server, so use only a trusted endpoint. Embedded credentials, query strings, and fragments are rejected.
The variable must exist in the Jellyfin server process environment before Jellyfin starts. Use a dedicated JELLYCAP_ variable and restart Jellyfin after changing it. Standard provider variables are accepted only with that provider's default endpoint.

Options labeled “with AI” use the configured provider. The community rating average is calculated locally from eligible collection members.

iAllows metadata and any API key to be sent without transport encryption. Loopback HTTP endpoints do not require this option.
iAI writes a collection overview from eligible item metadata, using the selected style, language, spoiler, and length settings.
iAI selects genres from the configured genre vocabulary, or from genres already present on eligible collection members.
iAI suggests discovery tags describing shared themes, settings, eras, styles, or audiences.
iAI proposes a concise collection sort title while preserving useful franchise ordering words or numbers.
iAI chooses one exact content rating already present on eligible collection members. It cannot invent or translate a rating.
iJellyCAP locally averages every eligible member with a Jellyfin community rating and rounds the result to one decimal. Unrated items are ignored.
iWhen enabled, AI suggests a 0–10 community rating from the supplied child ratings instead of using the locally calculated average.
iAllows the AI-generated overview to mention endings, deaths, and late-story revelations when useful.
Suggestions are limited to exact ratings found on eligible collection members.
Uses the one-decimal average of every eligible rated member unless the AI option is enabled. Ratings without a value are ignored.
Additional collection requests remain queued. Lower this if your provider enforces strict rate limits.
Spaces provider request start times across the server. Use 0 for no delay. Requests can still overlap when concurrent generations is above 1. Applies to queued generations and connection tests.
Applies to approved, rejected, and no-change results. Use 0 to remove them immediately.
Combined approved, rejected, and no-change history. Use 0 to keep none. Pending proposals are never removed.
